The core safeguard

Technical detail

Default after ok init: the bound launcher checks repository identity, physical root, authority, branch, revision, and NEXT context before printing a task. It does not judge the task or run it.

Read-only checks

ok -C . status --json
ok -C . next

Reviewed replacement

ok -C . next-write …

Mechanical check — current context, on-disk identity

Overseer compares the current checkout with the handoff on disk: repository UUID and root, selected authority, branch, revision, lane, model label, and prior digest. A mismatch stops instead of silently printing stale instructions.

Trusted NEXT

  • One handoff — next validates and prints the repository’s sole current task.
  • Exact context — copied configuration, a foreign handoff, or a stale revision refuses closed.
  • Your agent stays yours — Overseer prints task text; it never executes the prompt or chooses the work.

Repository · Revision · NEXT

  • Repository — a persistent UUID and exact physical root bind the local configuration.
  • Revision — freshness follows the current Git commit or selected Muse revision.
  • NEXT — one canonical handoff carries the reviewed task and its context.
  • Replacement — next-write requires the previous NEXT digest and explicit current context.

The failure mode

Why governance honesty matters

AI-assisted work breaks down when a new session starts from the wrong context.

  • Amnesia

    Each new chat re-derives context from scratch.

  • Wrong repository

    A plausible prompt is pasted into a similar checkout.

  • Silent drift

    A handoff outlives the branch or revision that produced it.

  • Unreviewed replacement

    Task text changes without checking its prior digest or context.

Overseer Kit makes context visible before work continues — a local handoff tool, not a hosted agent or workflow engine.

The loop

How it works

Bind the repository, inspect current status, read the trusted handoff, and replace it deliberately.

  1. 01

    Initialize explicitly

    Bind one authorized checkout to its persistent identity, physical root, authority, lane, and model label.

  2. 02

    Check status

    See the active repository, authority, branch, revision, runtime pin, and current NEXT digest.

  3. 03

    Read trusted NEXT

    Validate and print the task for your agent. Overseer does not execute it or decide whether it is good.

  4. 04

    Replace deliberately

    Review new task text, then publish it against the current revision and the exact prior NEXT digest.

Get started

This site is informational. Install the local CLI from the reviewed release, then choose Git or Muse authority for a repository you are authorized to manage.

Path 1 — Git-only permanent · no account

  1. Follow the reviewed v1.0.0-rc.1 INSTALL-AND-ROLLBACK.md guide.
  2. Set PROJECT_ROOT to an existing Git checkout you are authorized to initialize.
  3. Run ./cli/ok for init --vcs git with the required repository name and context.
  4. Use the repository-bound launcher for status, next, and a reviewed next-write.

Git-only is a complete ongoing mode. It requires no Muse installation, account, or future migration.

Path 2 — Muse authority (adopt)

  1. Read the Muse adoption and rollback guide before changing repository authority.
  2. Prepare the separate pinned Muse environment; Muse is not required by the core install.
  3. Preview adopt and confirm the repository identity, root, branch, and revision.
  4. Apply the authority change explicitly; Muse metadata alone never changes a Git binding.

Path 3 — Muse + GitHub mirror

  1. Prepare and verify the controlled projection with mirror; inspect source and destination identities.
  2. Explicit delivery may push the mirror and open a pull request. It never merges the pull request.

Overseer is bound to one local checkout. It prints a task; it does not execute the prompt, judge the task, or merge code.

Muse when it fits the repository

Git-only remains a complete ongoing mode. Muse can become the explicit repository authority, with or without a controlled GitHub mirror. The choice belongs to each repository.
