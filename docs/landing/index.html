Context check — the right task for this exact checkout

A copied prompt should not become another project’s work. Overseer compares on-disk identity and current version-control state before it prints the trusted handoff. A mismatch stops the read and leaves the task untouched.

One trusted NEXT

  • Readable — a plain-text task you can inspect before using it.
  • Bound — repository, branch, revision, lane, model label, and action identity travel with it.
  • Deliberate — replacing it requires the prior NEXT digest.

Repository · Branch · Revision

  • Repository — persistent UUID plus exact physical-folder binding.
  • Branch — confirms the workstream named by the handoff.
  • Revision — detects when work moved after the task was written.
  • Authority — Git or Muse is chosen explicitly for each repository.

The failure mode

Why context honesty matters

AI-assisted work breaks down when a good prompt is detached from the repository state that made it true.

  • Wrong repository

    A handoff copied from a similar project looks plausible.

  • Stale revision

    The branch moved after the task was written.

  • Lost handoff

    A new session reconstructs intent from partial memory.

  • Accidental replacement

    A task is overwritten without proving which version it replaced.

Overseer makes the handoff inspectable — and refuses to present it when its repository context no longer matches.

The real flow

How it works

Initialize once. Check the context. Read NEXT. Publish a reviewed replacement only when the task changes.

  1. 01

    Initialize the repository

    Choose Git or Muse explicitly, then bind the repository’s persistent identity and physical root.

  2. 02

    Check status

    See the active authority, repository, branch, revision, lane, model label, and NEXT digest.

  3. 03

    Read trusted NEXT

    Validate and print the handoff. Overseer does not run it or decide whether the task is good.

  4. 04

    Replace it deliberately

    Review the new task and publish it with exact context plus the previous NEXT digest.

Small by design

What Overseer does — and does not do

  • Local CLI

    It runs in a repository you are authorized to manage.

  • No automatic execution

    It prints a task; it does not run the prompt.

  • No automatic merge

    Mirror delivery may open a pull request; the operator reviews and merges.

  • No hosted product

    No service, desktop app, background process, telemetry, or updater.

Hooks are optional and off by default. Overseer protects against stale context and ordinary mistakes on a trusted host; it is not a security boundary against a malicious administrator.
