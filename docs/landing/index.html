CONTEXT BEFORE ACTION

A copied prompt should not become the wrong project’s task.

Know the repository

A persistent repository identity and exact physical-folder binding distinguish similar checkouts.

Know the moment

Branch and authoritative revision checks catch a stale handoff when the work has moved on.

Know what changed

Lane, model label, action identity and prompt checks protect the handoff. A replacement requires the previous NEXT digest.

The model label is declared context; Overseer does not verify which AI model is running or judge the task’s quality.

THE EVERYDAY FLOW

Four commands. An explicit handoff.

  1. 01

    Initialize a repository

    Choose Git or Muse explicitly. Bind the checkout’s physical folder and repository identity.

    init
  2. 02

    Check the context

    Read the repository, branch, revision, lane, model label and NEXT status.

    status
  3. 03

    Read the trusted task

    Validate the handoff before copying it into your work session. Overseer does not run it.

    next
  4. 04

    Publish a reviewed replacement

    Choose the next task yourself. Supply its context and the previous NEXT digest to publish it.

    next-write

Permanently supported. No Muse installation, no Muse account and no migration requirement.

Muse-only

Explicitly initialize or adopt Muse authority for a repository. Freshness follows its Muse branch and revision.

Muse + GitHub mirror

Small by design.

A local command-line tool. No hosted service, desktop product, background process, telemetry, automatic updater, registry or OCI system.

Overseer does not run prompts, choose the next task, merge automatically, release automatically or deploy automatically. Hooks are optional and off by default.

It protects against stale context and ordinary mistakes on a trusted host. It is not a boundary against a malicious administrator.
