The power feature

Technical detail

Default after ok init: L0 honesty gates are on — freeze review before Auto, build verification before DONE (diffs vs freeze, not the agent’s word). Domain L1 byte-check scripts are off until you set checkpoints.enabled: true and ship consumer verify scripts (what video pipelines add at many steps).

L0 (on by default)

ok review --freeze docs/PHASE-….md
ok check-ok --path docs/reviews/….md

L1 (opt-in)

ok verify-step --through current

Mechanical check — your bar, on-disk evidence

You define what “done” means: a frozen plan, required files, hashes, diffs, test exits, or your own scripts. Independent review and verify steps compare the work on disk against that bar — not the agent’s summary. Customize the checks for research, finance, academics, classrooms, or code; pass only when the evidence matches.

Check OK

  • Any work — type Check OK (or run ok check-ok) on a side spike, a draft, or a full phase. No roadmap row required.
  • Same honesty loop — freeze the plan, review it independently, then build and verify. Findings go back around until pass.
  • Anywhere you work — Cursor, Claude Code, or the terminal. One gate for ad-hoc work and larger phased projects.

Roadmap · Handover · Lanes

  • Roadmap — the phase board: what is planned, frozen, building, or done.
  • Handover — the session baton: what just landed and the one next prompt to paste.
  • Lanes — more than one roadmap/handover pair when several streams of work run in parallel.
  • Hygiene — sync roadmap and handover every session; commit the feature branch; no dirty tree at close.

The failure mode

Why governance honesty matters

AI-assisted development breaks down at the boundaries between sessions.

  • Amnesia

    Each new chat re-derives context from scratch.

  • Self-approval

    Phases get marked complete without independent review.

  • Silent drift

    Living docs fall out of sync with reality.

  • Skipped checkpoints

    Expensive remakes when mechanical gates are bypassed.

Overseer Kit makes skipping honesty expensive — not by running your product, but by governing how phased work proceeds.

The loop

How it works

Lock the plan, check it independently, then build only against that freeze. Living docs carry the baton between chats.

  1. 01

    Lock the plan

    Design freezes what to build and how. No build claims DONE until an independent freeze review passes.

  2. 02

    Keep docs truthful

    A phase board and a session handover stay aligned with real work — so the next chat starts from facts, not memory.

  3. 03

    Spend models wisely

    Use deeper judgment for design and review; keep mechanical build on a cheaper tier. The kit is the rulebook; your IDE dials the model.

  4. 04

    Close clean

    Before you stop, sync living docs to real VCS state and verify the build claim. Green tests alone cannot fake completion.

Get started

This site does not run the console and does not mint session credentials. Open a local process, then use the UI in the browser or desktop shell.

Path 1 — Download Mac console preferred · Apple Silicon

  1. Confirm Python 3.11+ (python3 --version).
  2. Download the signed Apple Silicon .dmg via the button above (Release v0.1.0).
  3. Set OVERSEER_REPO_ROOT to a repo that already has .overseer/ from ok init. Without it, the app binds the bundled kit inside the app.
  4. Open the app and confirm the bound path before any write action.

Apple Silicon Mac · signed and notarized · Python 3.11+ required. Windows/Linux signed installers are not published yet.

Path 2 — Browser (ok app)

  1. From a governed repo: ok app --open.
  2. Open http://127.0.0.1:8765/ on this machine only (this public page is static).
  3. From that same terminal, paste session_credential and csrf_token into Session bootstrap → Connect.
  4. Credentials last for the process only; never commit them; this website never mints them.

Path 3 — Dev desktop

  1. From kit root: ./scripts/bundle-desktop-kit.sh, then cd desktop && npm install && npm run tauri dev.
  2. Same bind rules as Path 1; needs Python 3.11+ plus Rust/Node for dev builds.

The console is bound to one local checkout — not to this website and not to arbitrary remote repos.
